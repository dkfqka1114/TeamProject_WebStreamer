# 시스템 프로그래밍 팀 프로젝트 - Web Streamer

## 프로젝트 개요

**Web Streamer**는 C 언어의 소켓 프로그래밍을 기반으로 구현한 웹 기반 스트리밍 및 실시간 채팅 시스템입니다.

웹 브라우저에서 회원가입과 로그인을 수행한 뒤, 사용자는 방송을 송출하거나 다른 사용자의 방송을 시청할 수 있습니다. 또한 방송방에 접속한 사용자들은 같은 채팅방을 공유하며 실시간으로 메시지를 주고받을 수 있습니다.

본 프로젝트는 시스템 프로그래밍 수업의 팀 프로젝트로, C 소켓 서버, HTTP 요청/응답 처리, 파일 입출력, 멀티스레드, mutex를 이용한 공유 자원 동기화 등을 직접 구현하는 것을 목표로 하였습니다.

## 주요 기능

### 1. 회원가입 및 로그인

사용자는 웹 페이지에서 ID와 비밀번호를 입력하여 회원가입을 할 수 있습니다.  
회원 정보는 서버의 `users.txt` 파일에 저장되며, 로그인 시 해당 파일을 읽어 입력한 ID/PW와 일치하는 계정이 있는지 확인합니다.

로그인에 성공하면 쿠키를 이용해 사용자의 로그인 상태를 유지합니다.

**동작 흐름**

```text
ID/PW 입력 → users.txt 확인 또는 저장 → 인증 결과 응답 → 쿠키 저장
```

---

### 2. 메인 화면 및 방송 목록

로그인한 사용자는 메인 화면으로 이동합니다.  
메인 화면에서는 현재 활성화된 방송 목록을 확인할 수 있으며, 방송 시작 또는 방송 시청을 선택할 수 있습니다.

**동작 흐름**

```text
로그인 확인 → 메인 HTML 로딩 → 활성 방송 목록 조회 → 브라우저 응답
```

---

### 3. 방송 송출

방송자는 브라우저에서 화면 공유를 시작할 수 있습니다.  
브라우저는 캡처된 화면을 JPEG/base64 형식의 데이터로 변환하여 서버로 전송합니다.

서버는 방송방별로 최신 프레임을 저장하고, 시청자가 요청할 때 해당 프레임을 제공합니다.

**동작 흐름**

```text
화면 캡처 → JPEG/base64 변환 → 서버 전송 → 방송방 버퍼에 최신 프레임 저장
```

---

### 4. 방송 시청

시청자는 방송 목록에서 원하는 방송을 선택하여 시청 페이지에 접속합니다.  
브라우저는 주기적으로 서버에 최신 프레임을 요청하고, 서버가 반환한 base64 JPEG 데이터를 화면에 렌더링합니다.

**동작 흐름**

```text
방송방 접속 → /live 주기적 요청 → 최신 프레임 수신 → 브라우저 렌더링
```

---

### 5. 실시간 채팅

방송자와 시청자는 같은 방송방의 채팅 목록을 공유합니다.  
사용자가 메시지를 보내면 서버는 해당 메시지를 방송방의 채팅 목록에 저장하고, 클라이언트는 주기적으로 채팅 목록을 요청하여 새 메시지를 확인합니다.

**동작 흐름**

```text
메시지 전송 → 서버 채팅 목록 저장 → JSON 조회 → 채팅창 갱신
```

## 사용 기술

### 1. C Socket Programming

C 언어의 소켓 API를 사용하여 웹 브라우저와 통신하는 HTTP 서버를 구현하였습니다.

사용한 주요 함수는 다음과 같습니다.

```text
socket() → bind() → listen() → accept() → read() → write()
```

---

### 2. 파일 입출력

회원가입 및 로그인 기능을 구현하기 위해 사용자 정보를 `users.txt` 파일에 저장하고 읽어옵니다.

사용한 주요 함수는 다음과 같습니다.

```text
fopen(), fscanf(), fprintf(), fclose()
```

---

### 3. 멀티스레드

여러 클라이언트가 동시에 접속할 수 있도록 `pthread`를 사용하였습니다.  
클라이언트가 접속할 때마다 새로운 스레드를 생성하여 각각의 요청을 독립적으로 처리합니다.

```text
Client 접속 → accept() → pthread_create() → 각 클라이언트 요청 처리
```

---

### 4. Mutex 동기화

여러 사용자가 동시에 방송 송출, 방송 시청, 채팅 등을 수행할 수 있기 때문에 공유 자원에 대한 동시 접근 문제가 발생할 수 있습니다.

이를 방지하기 위해 `pthread_mutex_lock()`과 `pthread_mutex_unlock()`을 사용하여 공유 자원 접근 구간을 보호하였습니다.

```text
pthread_mutex_lock()
→ 공유 데이터 접근 및 수정
→ pthread_mutex_unlock()
```

동기화가 필요한 주요 공유 자원은 다음과 같습니다.

- 사용자 정보 파일 `users.txt`
- 방송방 목록
- 방송 프레임 데이터
- 채팅 메시지 목록

---

### 5. HTTP Polling

방송 시청과 채팅 기능은 클라이언트가 서버에 주기적으로 요청을 보내는 HTTP Polling 방식으로 구현하였습니다.

- 방송 시청: 주기적으로 최신 프레임 요청
- 실시간 채팅: 주기적으로 채팅 목록 요청

## 주의 사항

- 서버는 기본적으로 `8080` 포트를 사용합니다.
- 프로그램은 프로젝트 루트 디렉터리에서 실행해야 합니다.
  - HTML 파일 경로가 `./html/` 기준으로 설정되어 있기 때문입니다.
- `users.txt`는 사용자 정보를 저장하는 파일입니다.
  - 학습용 프로젝트이므로 비밀번호 암호화는 적용되어 있지 않습니다.
- `localhost`가 아닌 외부에서 접속할 경우, 기본적으로 HTTPS 환경이 아니기 때문에 브라우저 보안 정책상 화면 캡처가 작동하지 않을 수 있습니다.
- 외부에서 원활하게 접속하기 위해서는 서버의 `8080` 포트를 개방해야 합니다.
- 브라우저 설정 또는 실행 환경에 따라 화면 공유 권한 허용이 필요할 수 있습니다.
- 현재 스트리밍 방식은 HTTP Polling 기반 JPEG 프레임 전송 방식이므로 실제 스트리밍 프로토콜에 비해 성능과 네트워크 효율성에는 한계가 있습니다.

## 배운 점

- C 소켓 서버를 직접 구현하며 HTTP 서버의 기본 동작 원리를 이해하였습니다.
- 클라이언트와 서버가 소켓을 통해 연결되고 데이터를 주고받는 과정을 학습하였습니다.
- `pthread`를 활용하여 여러 클라이언트 요청을 동시에 처리하는 방법을 익혔습니다.
- `mutex`를 이용하여 공유 자원 접근을 안전하게 제어하는 방법을 이해하였습니다.
- 파일 입출력을 활용하여 사용자 정보를 저장하고 인증하는 구조를 구현하였습니다.

## 개선할 점

- 현재는 HTTP Polling 기반 JPEG 프레임 전송 방식이므로 성능 및 네트워크 효율성에 한계가 있습니다.
- 실제 서비스 수준의 스트리밍을 위해서는 RTMP, HLS, WebRTC 등의 스트리밍 프로토콜 적용이 필요합니다.
- 사용자 비밀번호 암호화 및 세션 관리 강화가 필요합니다.
- 방송 화질 선택, 녹화, 알림 등 추가 기능을 구현할 수 있습니다.
- 서버 종료 시 방송방 및 채팅 데이터가 유지되지 않으므로 영속 저장 기능을 추가할 수 있습니다.
